# Session 2026-09-25 — Correcting documents at their generator, and the class of bug that hides there

## 0. Session at a glance

Before this session the submission package `submission/LOCKSMITH_DEV/` existed and
validated, but a correction made to one of its documents the previous day had **silently
vanished**. The document had been edited by hand; it is generated by a script; the next
build overwrote it. That single incident turned out to be an instance of a *class*, and
this session was spent finding the rest of the class, fixing each one **at its generator**,
and building a check that fails the build when the class recurs.

What exists now: two package documents corrected at their source, a second orphaned
document found and repaired structurally, a new validator check (`check_docs_against_scores`)
that cross-checks every metric value a packaged document asserts against a recomputation
from the package itself, a shared template module so two packaging scripts can no longer
drift, a corrected error-rate claim that was wrong inside a shipped deliverable, and a
six-slide pitch deck rebuilt from the packaging run. `VALIDATION PASSED`, Challenge 1 =
**94.0**, Challenge 2 = **93.6**. Nothing is still running.

**Prerequisites for this doc:** none specific. It defines its own terms. Some numbers
reference earlier work — where they do, the earlier session doc is linked rather than
restated at length. Useful but not required:
[[2026-09-22-published-withdrawn-and-the-fix-that-killed-the-antibody|the session that established diffusion_samples=1 makes model_0 an argmax]]
and [[2026-09-22-calibrating-the-rubric-against-things-that-should-fail|the calibration panel of 40 crystals]].

## 1. The problem this session addressed

A **submission package** is a directory of files handed to an external grader. In this
project it contains, per challenge, a protein structure (`.pdb`), a sequence file
(`.fasta`), a predicted-aligned-error matrix (`.json`), a metrics table (`scores.md`), and
two prose documents (`methods_and_limitations.md`, `reproducing_our_numbers.md`).

Every one of those files is **generated** by a Python script. None is hand-maintained.

That fact is easy to know and easy to forget, and forgetting it produces a specific,
silent failure:

> You find an error in a packaged document. You open the document and fix it. You verify
> the fix by reading the document. The fix is real and correct. Then anything rebuilds the
> package, the generator rewrites the file from its internal template, and your correction
> is gone — while your report says it was made.

This had just happened. The previous day's correction to Challenge 1's
`reproducing_our_numbers.md` was reverted by a packaging run (+11 −61 lines), restoring
text that told a grader to run DockQ with a flag value that **exits 1 and prints nothing**.
Because §7.2 of the handbook makes DockQ a hard viability cutoff, a grader following that
instruction could record "no DockQ" and mark Challenge 1 non-viable — a 94-point item.

The task was therefore not "fix the document" but three things:

1. Fix it **at the generator**, and verify from the *rebuilt* file rather than from the edit.
2. Audit the whole class: for every fix made, was it applied to a generated file or to its
   generator? Which packaged files are generated at all?
3. Add a check that **fails loudly** when this recurs.

## 2. Concepts introduced (first principles)

### 2.1 Generated artefact vs. source of truth

A file is a **generated artefact** if some program writes it from other inputs. The inputs
plus the program are the **source of truth**; the artefact is a *projection* of them.

The invariant is: *editing a projection does not change what it is a projection of.* The
edit survives exactly until the projection is recomputed. In a build system this is
obvious; in a directory of Markdown files that look hand-written it is not, because nothing
about a `.md` file announces that a script owns it.

**Transferable principle.** Before editing any file, ask *what writes this?* If something
does, edit that instead. The general form of the rule: **an edit to a derived object has a
lifetime bounded by the next derivation.** This is why compiled output, lockfiles, generated
API clients, migration files, and `README` sections built from docstrings all carry warning
banners in mature projects — and why a project without those banners will lose edits.

The cheapest detector, requiring no knowledge of the codebase, is a **timestamp
comparison**: if sibling files in a generated directory have materially different
modification times, one of them was not written by the last run.

### 2.2 Orphaned artefact

A stronger version of the same bug. Suppose two generators, `A` and `B`, can both produce a
package. `A` writes files `{w, x, y, z}`. `B` writes `{w, x, y}` — it simply does not know
about `z`.

Run `A`, then later run `B`. The package now contains `z` from `A` and `{w, x, y}` from `B`.
File `z` is an **orphan**: it describes an input that is no longer present, and *no generator
will ever correct it*, because the generator that owns it is not the one being run.

This is worse than the reverted-edit case because there is no moment at which anyone
observes something being undone. Every per-file check passes: `z` exists, parses, is
internally consistent, and its numbers are all real numbers that were true once.

**Transferable principle.** **A partial writer is more dangerous than a broken one.** When
two code paths can produce the same output, the one that produces *less* leaves stale
residue behind, and residue is invisible to any check that examines files one at a time.
Detecting it requires a **cross-check**: compare the artefact against a recomputation from
its declared inputs.

### 2.3 Value provenance

A number in a document has **provenance**: the computation and the inputs that produced it.
Two numbers can be individually correct and jointly wrong, because they came from different
inputs.

This session's sharpest instance: a document about design *D* quoted three DockQ values that
were genuine measurements — of design *D′*, which differs from *D* at one amino-acid
position. Nothing about the numbers is false. They answer a different question.

**Transferable principle.** **"Is this number right?" is the wrong question; "what is this
number *of*?" is the right one.** A value quoted from a results table is of unknown
provenance until you read what produced it. (This project has recorded the same lesson
before, from a case where a single-seed value was compared against an 8-seed mean.)

### 2.4 Rounding across a decision boundary

Background needed to read §3.1. A **banded score** maps a continuous metric to a discrete
label by thresholds, e.g. for DockQ:

```
good   if x >= 0.80
medium if x >= 0.49
...
```

and each band is worth a fixed number of points. Now suppose the value is obtained by
parsing a tool's *printed* output, which is rounded to 3 decimal places, and then compared
against the threshold.

Let `t` be the threshold and `p` the printed precision (here `p = 3`, so the rounding unit
is `10^-3` and the half-width is `ε = 0.5 × 10^-p = 0.0005`). Any true value `x` in the
interval

```
[t − ε, t)
```

prints as `t` and is therefore banded **above** the threshold although it lies below it.
Here `t = 0.80`, `ε = 0.0005`, so any true DockQ in `[0.7995, 0.800)` is misbanded.

The submitted design's true DockQ is **0.7995794972281312** — inside that interval by
**0.00042**. It printed `0.800`, banded `good`, and scored 2 points it had not earned.

**Transferable principle.** Rounding is harmless *except within half a display unit of a
decision boundary*. Wherever a rounded value feeds a threshold comparison, the error rate is
not "small" — it is **1 for values in that interval and 0 elsewhere**. Read the unrounded
value, or record that you could not.

## 3. What was built — mechanism, not narrative

### 3.1 The DockQ documentation, corrected at the generator

**Where the template lives.** `scripts/57_build_submission.py` contains the Challenge 1
package text inline, in two separate places:

| region | form | feeds |
|---|---|---|
| ~line 125 | a Python `list[str]` named `metrics_md` | `metrics/scores.md` |
| ~line 384 | an f-string named `repro_md` (opens line 368) | `docs/reproducing_our_numbers.md` |

Both contained stale DockQ text. The previous day's edit had touched *one line* of the
second region (hardcoding a total) without noticing the wrong paragraph four lines above it,
and had then patched the generated artefact instead of the template.

**Re-measured before writing** — the whole point being that nothing gets published in a pass
that was not verified in that pass. Five invocations, on the shipped structure against
`data/refs/prepared/5ggs_ABZ.pdb`:

| invocation | exit | result |
|---|---|---|
| `DockQ model native` (defaults) | **1** | `ERROR:root:For chains ['A'] no identical corresponding chain was found`, empty stdout |
| `--allowed_mismatches 15` | **1** | fails |
| `--allowed_mismatches 16` | 0 | `Total DockQ over 3 native interfaces: 0.800` |
| `--mapping ABC:ABC` alone | 0 | 0.800 |
| `--allowed_mismatches 40 --mapping ABC:ABC` | 0 | 0.800 |

So the document's claim that the minimum working value is **15** was false: 15 exits 1, and
**16** is the minimum, established by bisection.

**The claim underneath it was false too, and stayed false in the first attempt to fix it.**
The document justified the flag value as "exactly the number of substitutions in this
design". Aligning the shipped model against the native with `difflib.SequenceMatcher`
(global, `autojunk=False`) gives, per chain:

```
chain A (heavy):  native 219 -> model 232   substitutions 10, insertions 16, deletions 4
chain B (light):  native 217 -> model 218   substitutions  0, insertions  1, deletions 0
chain C (antigen):native 113 -> model 123   substitutions  0, insertions 10, deletions 0
```

The design carries **10** aligned substitutions, not 15 and not 16. (A naive *positional*
diff instead reports 197 substitutions on chain A, because the chains differ in length and
the comparison goes out of register — visible immediately in the output as `V1Q Q2V L3Q V4L`,
a shift, not a mutation pattern. That is a useful tell: **a substitution list that reads like
a rotation of the alphabet is an alignment failure, not a result.**)

Therefore the corrected text states 16 **as measured, with no derivation**, and explicitly
does not claim to know what DockQ counts internally. This is a deliberate choice: a false
mechanism is worse than an acknowledged gap, and two successive attempts to supply one had
both been wrong.

**Per-interface values, and a wrong explanation caught before publication.** The document
listed `A,B 0.931 / A,C 0.723 / B,C 0.794`. Recomputing from `--json` on the shipped
structure gives:

```
GlobalDockQ : 0.7995794972281312
  AB: DockQ=0.8716  LRMSD=0.931  iRMSD=0.839  fnat=0.865
  AC: DockQ=0.7308  LRMSD=2.015  iRMSD=0.738  fnat=0.441
  BC: DockQ=0.7963  LRMSD=1.970  iRMSD=1.026  fnat=0.759
```

The first explanation written — that `0.931` was the **LRMSD** column misread as DockQ — is
*wrong*, and was caught before it reached the file. `AB`'s LRMSD is indeed 0.931, which
makes the story seductive; but it explains only one of the three numbers. Recomputing the
five-sample diffusion sweep stored in `runs/diffusion_samples/ds_ch1_scores.json` gives for
its `model_0`:

```
model 0: Global=0.8160  AB=0.9307  AC=0.7229  BC=0.7945
```

All **three** match. The numbers came from a different structure. Confirmed definitively by
comparing sequences: the sweep's `model_0` and the shipped design differ at exactly one
position — heavy chain 55, `N` → `Q` — i.e. the sweep was run on the **pre-`N55Q`** design,
before the deamidation fix described in
[[2026-09-22-fixing-liabilities-and-refuting-our-own-advice|the session that removed the NG deamidation motif]].

**Knock-on defect found by the same trail.** `methods_and_limitations.md` presented that
sweep in a table whose first column was headed `0 (submitted)`, with DockQ **0.816** and
composite **96.0** — contradicting the corrected headline of 94.0 in the same package. The
label is simply wrong; sample 0 is not the submitted structure. Relabelled, with the
pre-`N55Q` provenance stated in the surrounding prose.

**Was the sweep itself affected by the rounding defect of §2.4?** Yes in mechanism, no in
consequence. `scripts/81_diffusion_samples.py:96` calls `dockq.compute(st, NATIVE)`, and the
sweep predates the `--json` fix, so its five values *were* parsed from the 3-dp printed
summary. Re-banding each sample at both the stored and the recomputed value:

| sample | stored | unrounded | band (stored) | band (unrounded) | composite |
|---|---|---|---|---|---|
| 0 | 0.8160 | 0.8160 | good | good | 96.0 |
| 1 | 0.7980 | 0.7979 | medium | medium | 94.0 |
| 2 | 0.8010 | 0.8011 | good | good | 96.0 |
| 3 | 0.8200 | 0.8201 | good | good | 96.0 |
| 4 | 0.7110 | 0.7109 | medium | medium | 94.0 |

No sample lies in `[0.7995, 0.800)`, so nothing flips. The table stands as published. This
is worth recording precisely because the honest answer was "defect present, consequence
nil" — reporting only defects that changed something teaches the wrong lesson.

### 3.2 The class audit

**Which packaged files are generated?** All of them. `src/locksmith/submit/package.py::build_challenge`
writes the FASTA, the PDB (copied), the PAE JSON, `metrics/scores.md` (from a `metrics_md`
argument) and `docs/methods_and_limitations.md` (from `docs_md`); any further documents
arrive through an `extra_docs: dict[str, str]` argument. **Nothing in `submission/` is
hand-maintained**, so a hand edit anywhere in that tree has a lifetime bounded by the next
build.

The session's other fixes had all landed in `src/locksmith/` — the library, which is
*upstream* of the generators — so they were safe.

**Then the orphan.** Two scripts can package Challenge 2:

- `scripts/75_challenge2_package.py` — passes `extra_docs={"reproducing_our_numbers.md": repro_md}`
- `scripts/105_package_bb8.py` — the script that swapped in the current `bb_8_0` design, and
  passes **no** `extra_docs`

The shipped package was built by 105. So `reproducing_our_numbers.md` was left exactly as 75
had written it, for the *previous* design. The timestamps show it plainly:

```
methods_and_limitations.md   2026-09-23 23:01:54
scores.md                    2026-09-23 23:01:54
design_1.fasta               2026-09-23 23:01:53
reproducing_our_numbers.md   2026-09-22 22:16:10     <-- a full day older
```

And the content contradicted the structure beside it:

| metric | stale doc asserted | package recomputes |
|---|---|---|
| `ipsae` | 0.781 | **0.904** |
| `netsolp` | 0.570 | **0.555** |
| `iface_plddt` | 85.17 | **88.62** |
| `cdr_sasa` | 1066.5 | **1110.5** |
| `contacts` | 97 | **99** |
| `cdrh3_identity` | 30.0 | **18.2** |

**The structural fix, not the textual one.** Editing the file would have re-created the
orphan on the next build. Instead the template was lifted verbatim out of `scripts/75` into
a new library module `src/locksmith/submit/docs.py` exposing

```python
def challenge2_repro_md(win: dict, conv: dict, team: str, heavy: str) -> str
```

and both packaging scripts now call it. `win` is documented as the **`model_0`** metric
dict — not the median across diffusion samples — because the package ships `model_0`, and a
reviewer recomputing from the packaged files will get `model_0`'s numbers. A template
reachable by only one of two generators is a bug waiting for the second generator.

**The other four files asked about:**

| file | generated by | verdict |
|---|---|---|
| `results/rubric_headroom.md` | `scripts/40_rubric_headroom.py` | **Stale** — uses midpoint bands (9.5/7.0/2.5, max 95.0) while config is `band_value=top`, and quotes a design at `dockq 0.747`. Does **not** ship. Left on the retraction list. |
| `results/m3_batching.md` | `scripts/34_verify_batching.py` | Clean — records an experiment (measured 1.16× against a projected 1.8×), not the submitted design. |
| `runs/throughput/results.json` | `scripts/108_throughput_arms.py:180` | Clean — raw measurement output. |
| Challenge 2 `reproducing_our_numbers.md` | `scripts/75` (not 105) | **The orphan.** Fixed as above. |

Challenge 2's *scores* were separately checked rather than assumed: re-running
`score.evaluate` on the shipped raw metrics with the current library reproduces the shipped
bands and subscores exactly, and raises no rounding risk — Challenge 2 has no DockQ (a de
novo design has no reference structure, §5.2) and nothing sits within its display precision
of an edge.

### 3.3 The guard: `check_docs_against_scores`

Added to `scripts/58_validate_submission.py`, which by design reads **only** the package —
it imports nothing from `runs/`, consults no cached score, and re-derives every metric from
the packaged files, because a check that reuses our own intermediate state proves nothing
about what a grader will see.

**Mechanism.** For each packaged `.md`, for each line, for each metric named in the line,
extract every number on the line and require at least one to match the recomputed value:

```python
nums = [float(x) for x in re.findall(r"-?\d+(?:\.\d+)?", line)]
t = float(truth)
ok = any(abs(n - t) <= max(5e-4, abs(t) * 1e-3)
         or round(n, 3) == round(t, 3)
         or (abs(t) >= 10 and round(n, 1) == round(t, 1))
         for n in nums)
```

The tolerance is deliberately *disjunctive* — absolute, relative, and two rounding
precisions — because documents legitimately print the same quantity at different precisions
(`0.904` and `0.9042` are the same number).

**Scope, and why each boundary is where it is.** This is the part that took the most
iteration, and the limits matter more than the coverage:

| context | checked? | why |
|---|---|---|
| table rows (`\|`-prefixed) | yes | where a value is *asserted* |
| prose | yes, if the metric appears in backticks **and** the line has a number | catches a value stated in a sentence |
| fenced blocks | **totals only** (line contains "total") | see below |
| conventions rows | **excluded** | see below |

*Conventions rows* name a metric but assert a **setting**, not a value —
`` | `netsolp` | `netsolp_chain_agg` | `min` | VH 0.699 vs VL 0.569 | `` — and carry unrelated
numbers such as section references and dates. They are excluded by testing the line against
the **live config keys** (`set(load().conventions) | {"band_value"}`), not a hand-kept list,
so a newly added convention cannot silently reintroduce the noise.

*Fenced blocks* are pasted tool output, and most of their lines are not comparable to the
aggregate: a shell command line carries the reference filename's digits (`5ggs_ABZ.pdb`),
and a **per-interface** row legitimately differs from the global value (`A,B 0.8716` vs
global `0.7996` — both correct). Only an explicit total is comparable.

**This leaves a real, named gap.** The `0.931 / 0.723 / 0.794` regression lived in exactly
those per-interface rows, and **a numeric cross-check cannot catch it**, because the numbers
were valid values of a different structure. Nothing about them is arithmetically wrong. That
case is covered only by `_BANNED`, a dictionary of five retracted strings keyed to the reason
each was wrong — and being a `grep`, it only ever catches a *repeat* of a mistake already
made once. The docstring says this explicitly, so that a passing run is not read as broader
assurance than it is.

**Second half: `_BANNED`.** Five keys, each a string that was wrong once and must never
return:

```
'works is 15'          -> the measured minimum is 16; 15 exits 1
'our 15 substitutions' -> never verified, and not the design's count
'the identical 0.816'  -> belongs to the pre-N55Q sweep, not the submission
'A,B  DockQ 0.931'     -> pre-N55Q sweep model_0, not the submitted design
'0 (submitted)'        -> mislabelled the sweep's model 0 as the submitted structure
```

### 3.4 Data flow, end to end, for one number

Following the shipped Challenge 1 DockQ value from tool to grader:

1. `dockq.compute()` runs `DockQ <model> <native> --allowed_mismatches 40 --mapping ABC:ABC
   --json <tmp>/dockq.json` and parses `GlobalDockQ` from the JSON → `0.7995794972281312`.
   It does **not** round its return value, because banding must see the true number.
2. `score.evaluate()` bands it: `0.79958 < 0.80` → `medium` → 8.0 points. It also records a
   `rounding_risk` entry, because the value lies within its display precision (`5e-4`) of
   the `0.80` edge.
3. `scripts/57` renders `scores.md` with adaptive precision — six decimals *only* where the
   rounding-risk flag fired — giving `| dockq | 0.799579 | medium | 8.0 |`, which reads as
   deliberate rather than as a bug.
4. `build_challenge()` writes the file; `build_zip()` archives the tree.
5. `scripts/58` re-derives all eight metrics from the archived files alone, and
   `check_docs_against_scores` confirms every document's assertions agree with them.

## 4. Design decisions

**Fix the template, not the artefact.**
*Chosen:* edit the generator; verify from the rebuilt file.
*Alternatives:* edit the artefact and remember not to rebuild; add the artefact to a
"do not regenerate" list.
*Why:* the artefact has no memory. Any future build silently discards the correction, and
the failure is invisible because the file still exists and still parses.
*Cost to reverse:* none — the template is plain text in the script.

**Quote 16 as measured, with no derivation.**
*Chosen:* state the bisection result and say we do not know what DockQ counts.
*Alternatives:* claim it equals the substitution count (the original, false); claim it
equals substitutions + the `N55Q` fix (the second attempt, also false — the design carries
10 substitutions).
*Why:* two successive derivations were wrong. A reader who is told "we measured it" can
reproduce it; a reader given a false mechanism will reason from it.
*Cost to reverse:* trivial, and should only be reversed by *measuring* the derivation first.

**Move the Challenge 2 template into the library rather than duplicating it.**
*Chosen:* one function, two callers.
*Alternatives:* copy the template into `scripts/105`; delete the orphan from the package.
*Why:* duplication re-creates the drift one generator at a time, and deletion removes a
document Challenge 1 ships, which a grader would notice as an asymmetry.
*Cost to reverse:* low, but reversing re-opens the orphan class.

**Replace the unverifiable germline figure rather than re-deriving it.**
*Chosen:* quote `best_segment`, computed from the shipped heavy chain.
*Alternatives:* recompute "global-alignment identity against all 6,864 IGHV×IGHD×IGHJ
recombinations" as written; delete the sentence entirely.
*Why:* the claim is not reproducible from this repository — the germline database holds
**249 V × 76 D × 14 J = 264,936** combinations, and 6,864 divides evenly by none of them. No
code here enumerates recombinations. The sentence made a genuinely useful point (the
convention moves the number), so it was preserved with a figure that *is* computed.
*Cost to reverse:* low; implementing the recombination enumeration would be a real piece of
work and would need validating.

**Restrict the fenced-block check to totals.**
*Chosen:* check only lines containing "total".
*Alternatives:* check every fenced line (produced 7 false positives on legitimate content);
check no fenced lines (the original, and the weaker half).
*Why:* per-interface values and shell command lines are not comparable to the aggregate, by
construction rather than by accident.
*Cost to reverse:* trivial — but widening it again will reintroduce the false positives
unless the per-interface case is handled by recomputing *per-interface* truth, which is the
honest next step.

## 5. What went wrong

### 5.1 Reporting a fix from the edit instead of from the rebuilt file

**What happened.** The previous pass patched the generated artefact, verified by reading
that artefact, and reported the DockQ documentation as fixed. A subsequent packaging run
reverted it (+11 −61). The summary claiming the fix stood was false at the time it was
written.

**Why it was dangerous.** The reverted text instructs a grader to use
`--allowed_mismatches 15`, which exits 1 with no output. Under §7.2 DockQ is a hard cutoff,
so this is a plausible route to Challenge 1 scoring **0** instead of 94.

**How it was caught.** The user diffed the package and found the correction absent.

**General lesson.** **Verify a fix from the artefact the consumer will read, produced by the
process that produces it** — not from the file you edited. "I changed it and looked at it"
is not evidence when something else owns the file.

### 5.2 A fabricated explanation, caught one step before publication

**What happened.** Explaining the wrong per-interface values, the first draft asserted that
`0.931` was the `AB` **LRMSD** column misread as DockQ. `AB`'s LRMSD *is* 0.931, so the
story was self-consistent — and wrong. All three values match the pre-`N55Q` diffusion sweep.

**Why it was dangerous.** It would have replaced a false claim with a *different* false
claim, in the same document, in the commit whose stated purpose was correcting false claims.

**How it was caught.** By recomputing the sweep instead of stopping at the first coherent
explanation. The tell was that the LRMSD story explained **one** of three numbers; a real
mechanism explains all of them.

**General lesson.** **A coincidence that explains part of the evidence is more dangerous
than no explanation at all**, because it terminates the search. Require an explanation to
account for every observation before accepting it — and prefer the provenance question
(§2.3) over the mechanism question.

### 5.3 Reading a pipeline's exit status as the script's

**What happened.** `scripts/57_build_submission.py` was run as
`python scripts/57_build_submission.py 2>&1 | tail -30`. The script crashed with
`ModuleNotFoundError: No module named 'pptx'` at the deck step. The reported exit code was
**0** — `tail`'s. The session report said "Rebuild finished exit 0".

**Why it was dangerous.** Three compounding effects. The deck — a **50-point** deliverable —
was never rebuilt, and had a modification time two hours older than the package. `build_zip`
sits at line 473, *after* the crashing call at line 471, so the zip was not rebuilt either.
And the package `.md` files *were* written, because `build_challenge` runs before the deck —
so the verification that was performed passed, on a package produced by a script that had
failed.

**How it was caught.** Inspecting the deck's modification time before building slides, and
noticing it predated the rebuild.

**General lesson.** This project has recorded that `grep … | head` "lies twice"; the same
applies to any pipeline. **`$?` after a pipeline is the last command's status.** Redirect to
a file and read the real status (`cmd > log 2>&1; echo $?`), or set `pipefail`. The
second-order lesson is worse: **a crash partway through a build leaves a directory that
looks complete**, so "the output files exist and validate" is not evidence the build
succeeded.

### 5.4 An undeclared dependency on a scored deliverable

**What happened.** `src/locksmith/submit/deck.py` imports `pptx`, and `python-pptx` appeared
nowhere in `pyproject.toml`. No interpreter on the machine had it; the previously shipped
deck had been built in an environment that no longer exists.

**Why it was dangerous.** The deck is worth up to 50 of 250 points, and the package could be
built — apparently successfully, per §5.3 — without it.

**How it was caught.** The crash in §5.3.

**General lesson.** **A dependency used only by the last step of a pipeline is the one most
likely to be undeclared**, because every earlier step succeeds without it and the failure
looks like a late-stage bug rather than a missing package. Declared it, and verified the
install did not disturb the pinned stack (`torch 2.11.0+cu128`, `numpy 2.5.3` unchanged
after pulling in `lxml`, `pillow`, `xlsxwriter`).

### 5.5 A guard whose first version missed the case it was written for

**What happened.** The numeric cross-check was extended from table rows to prose. The
mutation test — flipping the germline figure in the sentence — **did not fire**. The
sentence named the metric as "the V(D)J-coverage reading", not as `` `cdrh3_identity` ``, and
the prose rule requires a backticked metric name.

**Why it was dangerous.** The guard would have reported a clean package while the exact
value class it was extended to cover went unchecked.

**How it was caught.** Only by mutation-testing the *specific* sentence rather than
mutation-testing in general.

**General lesson.** **A guard is only tested by the mutation it was written to catch.**
Writing a plausible mutation elsewhere and watching the guard fire proves the guard runs,
not that it covers. The fix here was also instructive: rather than loosening the matcher
(which would add false positives), the *document* was changed to name the metric it asserts
— **write artefacts so the checker can see them.**

### 5.6 A mixed-threshold error rate, live in a shipped document

**What happened.** Challenge 2's `methods_and_limitations.md` claimed the ipSAE gate has
"a **0% false-positive rate** — it never accepted an incorrect pose in 40 tries — against a
**25% false-negative rate**." Recomputing from `runs/calibration/scores.json`:

| label threshold | positives | FP rate | FN rate |
|---|---|---|---|
| DockQ ≥ 0.23 (Acceptable+) | 36/40 | **0%** | **58.3%** |
| DockQ ≥ 0.49 (Medium+) | 16/40 | **12.5%** | **25.0%** |

The quoted pair takes the favourable half of each and **is reachable at neither**.

**Why it was dangerous.** It overstates the gate in both directions simultaneously, in a
document a grader reads, and it had survived four independent audits.

**How it was caught.** By recomputing the deck's slide-3 numbers from the panel data instead
of copying them from an earlier message. The figures had never been written to any file in
`results/` — they existed only in conversation.

**General lesson.** **Error rates are a property of a threshold, and quoting two of them
together asserts they share one.** More generally: a number that lives only in prose and
never in a data file has no provenance and cannot be re-derived; if it is worth stating, it
is worth computing in code.

## 6. Degenerate and failure cases

- **Value exactly on a band edge.** `x == 0.80` bands `good` (comparison is `>=`). The
  `rounding_risk` flag fires for anything within `±5e-4`, including the exact edge, because
  it flags the *condition*, not a verdict.
- **A metric absent for a challenge.** Challenge 2 has no DockQ. `check_docs_against_scores`
  skips any metric whose recomputed value is `None` rather than treating absence as a
  mismatch.
- **Document with no tables.** Handled — the loop simply finds no checkable lines. Note this
  means an all-prose document with no backticked metric names is **unchecked**, and that is
  a real hole, not a handled case.
- **Per-interface values in a fence.** Known-broken by design (§3.3). Covered only by
  `_BANNED`.
- **Config unreadable.** `_CONVENTION_KEYS` falls back to `{"band_value"}`, which makes the
  check *stricter* (more lines examined) rather than weaker — the safe direction.
- **Unmatched fence markers.** A document with an odd number of ``` lines leaves `in_fence`
  true to end of file, suppressing prose checks after that point. Not handled; not currently
  reachable because the templates are machine-generated.

## 7. Verification — how we know it works

**Mutation testing of the guard.** Each mutation applied to a *copy* of the package; the
control is the unmodified package. A guard that only ever passes is not evidence.

| mutation | validator exit | findings |
|---|---|---|
| table-row value `0.904` → `0.781` | 1 | 1 |
| prose value `18.2%` → `40.0%` | 1 | 1 |
| fenced total `0.800` → `0.931` | 1 | 1 |
| banned string reintroduced | 1 | 1 |
| **control: unmodified package** | **0** | **0** |

Before the Challenge 2 orphan was fixed, the same check found it unprompted, on **all seven**
of its metrics — which is the strongest evidence available that it detects the class rather
than the instance.

**Full validation, from the packaged files alone:**

```bash

    --reference data/refs/prepared/5ggs_ABZ.pdb
```

Healthy output ends `VALIDATION PASSED`, exit 0, with Challenge 1 `FINAL: 94.0` and
Challenge 2 `FINAL: 93.6`, both `VIABLE: True`.

**Zip verification, both directions.** Absence of a wrong string is *not* evidence the right
one is present — the same asymmetry as the silently-discarded-MSA lesson. So both were
asserted:

- Negative: **0 occurrences across all 5** `_BANNED` strings, with the key list read out of
  the source rather than from memory (an earlier report said "all four", which was wrong).
- Positive: `0.904`, `0.555`, `27.3%`, `18.2%`, `0.8716`, `0.7308`, `0.7963`, `works is 16`

**What a plausible-but-wrong result looks like.** `VALIDATION PASSED` on a package whose

specific tell is a **modification-time spread** inside one challenge directory. Worth
checking directly:

```bash

                submission/LOCKSMITH_DEV/LOCKSMITH_DEV_Challenge2/metrics/scores.md
```

Healthy: all timestamps within seconds of each other. A day's gap is the orphan signature.

## 10. Glossary

- **Artefact** — a file produced by a program from other inputs. Contrast *source of truth*.
- **Orphan** — an artefact left behind by a generator that a later, partial generator does
  not rewrite. Describes inputs no longer present.
- **Band / banded score** — mapping a continuous metric to a discrete label by thresholds,
  each label worth fixed points. `band_value=top` scores each band at its upper anchor.
- **CDR** — complementarity-determining region; the six antibody loops that contact antigen.
  CDR-H3 is the most variable and spans the V(D)J junction.
- **DockQ** — a 0–1 score comparing a predicted protein complex against a reference crystal
  structure. CAPRI bands at 0.23 (acceptable), 0.49 (medium), 0.80 (high).
- **`GlobalDockQ`** — DockQ v2's aggregate over all interfaces; the value this project bands.
- **ipSAE** — a confidence score derived from the predicted aligned error matrix, with a hard
  10 Å PAE cutoff; floors at 0.
- **LRMSD / iRMSD / fnat** — ligand RMSD, interface RMSD, and fraction of native contacts;
  the three components DockQ combines. Printed *beside* DockQ, which is how one gets
  misread as the other.
- **MSA** — multiple sequence alignment; the evolutionary input a structure predictor uses.
- **`model_0`** — the first model a predictor returns. Under `diffusion_samples=1` it is an
  **argmax by construction**, not a sample.
- **Mutation testing** — deliberately introducing a defect to confirm a check detects it.
- **NetSolP** — a sequence-only solubility predictor; this project uses the ESM1b variant and
  aggregates `min(VH, VL)`.
- **PAE** — predicted aligned error; per-residue-pair positional uncertainty, in Å.
- **Provenance** — the computation and inputs that produced a value.
- **Sequon** — the `N-X-S/T` motif that accepts N-linked glycosylation.
